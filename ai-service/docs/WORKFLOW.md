# AI Engineer Workflow — Duman Zhanbolatov

## Моя роль

Я реализовал отдельный Python AI-сервис для командного сайта продажи туров.
Go-backend отвечает за каталог и бизнес-данные, frontend — за окно чата, а мой
сервис — за агента, промпт, MCP/tools и память диалога.

## Архитектурное решение

```text
Frontend → Python POST /chat → OpenAI Tour Assistant
                                      ↓
                           local MCP over stdio
                           ├── search_tours
                           ├── get_tour_details
                           └── compare_tours
                                      ↓
                         Go /api/v1 API
```

Отдельный Python-сервис выбран, чтобы AI-часть была изолирована и имела понятный
контракт с Go. Каталог всегда читается из командного backend, поэтому агент
работает с теми же турами, которые видит frontend.

## Что сделал я

- подготовил системный промпт и ограничения агента;
- создал агента через OpenAI Agents SDK;
- реализовал настоящий MCP-сервер по stdio;
- добавил три инструмента для каталога туров;
- создал адаптер к Go API;
- добавил SQLite-память по `session_id`;
- реализовал `POST /chat` и `GET /health`;
- подготовил автоматические тесты и персональные AI rules.

## Как AI использует внешний контекст

Агент не получает список туров в системном промпте. При запросе пользователя он
обнаруживает MCP tools и вызывает `search_tours`. Инструмент читает каталог через
Go API и возвращает фактические данные. Название страны сначала
преобразуется через `/api/v1/countries` в `country_id`, затем поиск вызывается через
`/api/v1/tours`. Только после tool result агент формирует рекомендацию. Для
подробностей и сравнения используются отдельные MCP-вызовы.

## Память

После успешного ответа сообщения пользователя и агента записываются в SQLite.
При следующем запросе сервис загружает последние сообщения той же сессии. Поэтому
фраза «до 500000 тенге» может продолжить предыдущий запрос «хочу в Турцию».
Истории разных `session_id` не смешиваются.

## Проверки

Автотесты проверяют:

- валидацию HTTP-запросов;
- параметры запросов к Go API;
- ошибку недоступного backend;
- сохранение и изоляцию памяти;
- реальный запуск MCP-процесса и обнаружение трёх tools;
- передачу истории агенту без обращения к платному API.

## Сценарий демонстрации

1. Запустить Go-backend на `http://localhost:8080` и затем AI-сервис.
2. Отправить: «Хочу в Турцию» с `session_id=demo-1`.
3. Ответить в той же сессии: «До 500000 KZT, в сентябре».
4. Показать вызов `search_tours` и найденный тур в Анталию.
5. Запросить детали выбранного тура.
6. Показать корневой `ai-rules/ai_duman_zhanbolatov.md` и результаты `pytest`.
