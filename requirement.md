## 👥 Формат команд (гибкий)

Количество участников в команде может отличаться. Роли и критерии оценки адаптируются автоматически.

### 🧑‍🤝‍🧑 Команда из 4 человек (стандарт)

**Роли**
1. 🎨 Frontend Developer
2. ⚙️ Backend Developer
3. 🧠 AI Engineer
4. 🧪 QA Engineer & Workflow Master

**Оценка**
- Product: 4 × 12.5 = 50
- Workflow: 50

### 🧑‍🤝‍🧑 Команда из 3 человек

Допускается отсутствие роли AI Engineer.

**Роли**
- Frontend Developer
- Backend Developer
- QA / Workflow (или совмещённая роль)

**Оценка**
- 17 / 17 / 17 — индивидуальный вклад
- Workflow перераспределяется пропорционально

### 🧑‍🤝‍🧑 Команда из 2 человек (форс-мажор)

Например:
- у участника пропал интернет
- участник вылетел из команды

**Роли**
- Frontend Developer
- Backend Developer

Один из участников обязан:
- записать видео или
- полностью оформить WORKFLOW.md

**Оценка**
- баллы делятся поровну
- основной акцент — на workflow

## 🏗️ Состав команды и роли

### 🎨 Frontend Developer (UI / UX)

**Задачи**
- Интерфейс
- Компоненты
- Layout
- State-менеджмент

**Фокус**
- Генерация UI через промпты
- Минимум ручного JSX / CSS

**🚫 Запрещено**
- Чистый HTML + CSS + JS
- Отсутствие дизайн-системы
- Примитивный UI (кнопка + текст)

### ⚙️ Backend Developer (API & Data)

**Задачи**
- Архитектура БД
- API-эндпоинты
- Интеграции

**Фокус**
- Использование MCP:
  - схема БД
  - документация сервисов
- Генерация через промпты:
  - миграций
  - таблиц
  - API-логики

### 🧠 AI Engineer (Lead Architect)

(может отсутствовать в команде из 3 человек)

**Задачи**
- Архитектура агента
- Промпты
- Инструменты
- Память

> ⚠️ Использование просто GPT API без инструментов — недостаточно. AI обязан вызывать tools / MCP / sub-agents (что-то одно).

### 🧪 QA Engineer & Workflow Master

**Задачи**
- Автотесты
- Документация процесса
- Сбор доказательств использования AI

## 📦 Обязательное требование: персональные AI-rules

Каждый участник обязан добавить свой markdown-файл с правилами для AI-ассистента.

### 📁 Структура

```
/ai-rules/
  frontend_<name>.md
  backend_<name>.md
  ai_<name>.md
  qa_<name>.md
```

❗ Файл нельзя называть `Claude.md`, `GPT.md` и т.п. Файл = роль + имя участника.

### 📄 Содержимое каждого *.md (ОБЯЗАТЕЛЬНО)

```
# Role (Frontend / Backend / AI / QA)

# System Rules
- Роль AI
- Ограничения
- Чего делать нельзя
- Формат ответов

# MCP & Tools
- Какие MCP подключены
- Какие tools может вызывать AI

# Subagents (если есть)
- Назначение
- Когда вызываются

# Output Contracts
- JSON / SQL / JSX / Tests
```

❌ Нет файла → снижение баллов за Workflow.

---

## 🔌 MCP & Subagent Requirements

В проекте:
- каждая роль должна использовать минимум 1 MCP или sub-agent
- минимум 4 MCP / sub-agent на команду (если вас 4 человека)
- AI должен реально использовать внешний контекст

**Примеры MCP / sub-agent**
- Context7 MCP
- Playwright MCP
- Puppeteer MCP
- Code-analysis sub-agent

## 💡 Проекты

### 1️⃣ Платформа вакансий (LinkedIn / HH mini)

**Описание**: Веб-сайт с вакансиями и компаниями.

**Функционал сайта**
- Список вакансий
- Страница вакансии
- Компания + описание
- Фильтры (город, грейд, формат)

**AI (дополнительно)**
- Чат-бот:
  - помогает подобрать вакансии
  - отвечает на вопросы по вакансиям
  - может подсказать, что подтянуть

👉 Если AI нет — это просто нормальный job board.

### 2️⃣ Сайт по продаже туров

**Описание**: Платформа для подбора и бронирования туров.

**Функционал сайта**
- Список туров
- Страница тура
- Фильтры (страна, цена, даты)
- Бронирование (без реальной оплаты)

**AI (дополнительно)**
- Чат-бот:
  - помогает подобрать тур
  - учитывает бюджет и даты
  - объясняет отличия туров

👉 Без AI — обычный сайт туроператора.

### 3️⃣ Агрегатор университетов

**Описание**: Сайт с университетами и требованиями для поступления.

**Функционал сайта**
- Список университетов
- Страница университета
- Требования (баллы, экзамены)
- Фильтры (страна, специальность)

**AI (дополнительно)**
- Агент:
  - помогает выбрать университет
  - отвечает на вопросы
  - может сравнить варианты

👉 Без AI — обычный образовательный каталог.

### 4️⃣ Сервис выбора ресторанов / еды

(abr group / Glovo / Яндекс Еда mini)

**Описание**: Платформа с ресторанами и кафе.

**Функционал сайта**
- Список ресторанов
- Меню
- Категории кухни
- Корзина (без реальной доставки)

**AI (дополнительно)**
- Чат-бот:
  - помогает выбрать ресторан
  - советует блюда
  - учитывает бюджет и предпочтения

👉 Без AI — обычный food-каталог.

### 5️⃣ Сайт выбора поликлиники / медуслуг

**Описание**: Каталог медицинских учреждений и услуг.

**Функционал сайта**
- Список клиник
- Услуги
- Врачи
- Запись (форма)

**AI (дополнительно)**
- Чат-бот:
  - помогает выбрать услугу
  - объясняет, к какому врачу идти
  - отвечает на общие вопросы

👉 Без AI — обычный мед-сайт.

## ✅ Главное правило для всех проектов

- Сайт обязан работать и без AI
- Frontend + Backend — основа оценки
- AI:
  - усиливает UX
  - помогает пользователю
  - но не является единственным функционалом
