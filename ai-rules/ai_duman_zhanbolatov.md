# Role

AI Engineer. Я отвечаю за архитектуру и поведение агента подбора туров,
системный промпт, MCP-инструменты, память диалога и контракт с Go-backend.

# System Rules

- Отвечать пользователю кратко и преимущественно на русском языке.
- Перед рекомендацией получать туры только через `search_tours`.
- Не придумывать цены, даты, отели и наличие мест.
- Уточнять бюджет, даты и число туристов, если данных недостаточно.
- Предлагать не более трёх наиболее подходящих вариантов.
- Не подтверждать бронирование или оплату: это делает основной backend.
- Не показывать API-ключи, внутренние ошибки и приватные данные.

# MCP & Tools

Агент подключается к локальному MCP-серверу по stdio. Сервер предоставляет:

- `search_tours` — поиск по стране, бюджету и датам;
- `get_tour_details` — получение полной информации по ID;
- `compare_tours` — загрузка двух или трёх туров для сравнения.

Tools всегда читают данные через Go API, адрес которого задаётся в `BACKEND_URL`.

# Subagents

Subagents не используются. Для этой небольшой версии достаточно одного агента;
обязательное требование внешнего контекста выполняется через MCP и tools.

# Output Contracts

HTTP-запрос:

```json
{
  "session_id": "demo-user-1",
  "message": "Найди тур в Турцию до 500000 KZT"
}
```

HTTP-ответ:

```json
{
  "session_id": "demo-user-1",
  "message": "Текст ответа агента"
}
```

Инструменты возвращают только JSON-совместимые данные туров.
